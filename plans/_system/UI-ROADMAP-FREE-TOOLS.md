## 一条硬约束：只用免费工具

这个应用**不接任何付费套餐**。所有依赖必须是下面两类之一：

| 类别 | 具体 | 代价 |
|---|---|---|
| 完全本地 | ffmpeg / ffprobe、MoviePy、Pillow、whisper.cpp、Ollama | 你的电费与磁盘 |
| 带免费额度 | Pexels / Pixabay / Coverr（素材）；Groq、ModelScope、Pollinations、OpenRouter 的 `:free` 模型、云端 TTS 的试用额度 | 额度用完就失败，**不会扣费** |

已支持的免费 LLM 入口（`app/models/llm_provider.py` 的 Provider 表）：

- `ollama` — 完全本地，`requires_api_key=False`，装了就能用
- `pollinations` — 免费额度
- `modelscope` — 免费额度
- `groq` — 免费额度
- `openrouter` — 选 `:free` 后缀模型即可

界面上这一点不再只写在文档里：左侧导航底部常驻一张「免费工具」状态卡，逐项显示
脚本 / 素材 / 配音当前是否就绪（`_free_tool_readiness`）。它刻意**不显示额度数字**
——各家额度与刷新策略差异很大，写死在界面上很快会过期成谎言。

> ⚠️ 免费额度会变。上面任何一个服务商调整政策，这条约束就要重新评估。

## 导航为什么不是 `st.navigation`

`st.navigation` 更"正统"，但它把每个页面变成独立脚本，**AppTest 无法切页**——
媒体库、计划面板、设置页的几十个既有用例会同时失去被测能力。改用
`st.sidebar` 里的按钮 + 一个 `nav_view` session 键，外观一致，测试里一行
`app.session_state["nav_view"] = "plan"` 就能走到那一屏。

## 未实现：UI 已生成，标注为待实现

生成页底部有「更多工具（尚未实现）」折叠区，三张虚线占位卡。视觉上与已实现入口
**一眼可分**（虚线边框 + 灰底徽章 + 禁用按钮），不会让人以为是界面坏了。
每张卡的按钮 tooltip 写的是"要做出来需要什么"，而不只是"还没做"。

### 1. 视频编辑器（时间轴裁剪 / 排序 / 重新配字幕）

**要做出来需要什么**

- 时间轴数据模型：一条轨道 = 若干 `(素材, 入点, 出点, 转场)` 片段
- 一趟 ffmpeg 裁剪 + 拼接（`app/services/video.py::concat_video_clips_with_ffmpeg` 已经有雏形）
- 重新烧录字幕（`_build_subtitle_clip` 已经能用）
- 独立的编辑页 + 撤销

**成本判断**：渲染层能力基本齐备，这一步主要是接线和独立一屏，**不花钱**。
只有在"确实需要裁剪"时才值得做——现在的流程是从素材库重新出片，不是从成片改。

### 2. 广告变体（一稿多版）

**要做出来需要什么**

- 每条变体一次文生视频调用

**为什么不建议做**：这必然要按条付费的文生视频服务（WaveSpeed / Seedance /
Shengsuan 都是），与"只用免费工具"直接冲突；本地生成在笔记本上不现实。
**替代方案**：在脚本层面换开场钩子重新出片，成本已经在预算内。

### 3. 成片搜索

**要做出来需要什么**

- 给已有的月度计划文件建索引（`tools/plans.py::load_monthly_plan` 已经是结构化数据）
- 按主题 / 日期 / 文字检索

**成本判断**：完全本地、很便宜。等成片库拆成独立页面之后，大约一天工作量。

## 一个走错了又走回来的坑（记录下来免得再试一次）

任务表每 2 秒刷新一次，12 行任务带 12 组删除确认，每轮重建上百个控件，其中大部分
用户根本看不见。直觉方案是"弹层关闭时不渲染弹层内容"。**这条路是错的**，两个坑都踩过：

1. **内容为空 → 按钮变灰。** Streamlit 会把内容为空的 `st.popover` 直接禁用。
   任务管理器和每一行的删除按钮同时变灰点不动，**删除功能整个消失**。
2. **换 `st.empty()` 占位 → 弹层里是空白。** 按钮恢复正常了，但
   popover 的展开状态**不写进 `session_state[popover_key]`**，那道闸门在真实
   浏览器里永远读到 False。AppTest 里能通过是因为测试自己把键设成了 True，
   跟真实交互不是一回事。

结论与最终做法：不再跟 popover 的内部状态较劲。任务表**移出 popover**，改成主区域
里一个由 `task_manager_open` 控制的区块，关闭时一个控件都不产生。

顺带解决了一个体验问题——十几行带按钮的表格塞在弹层里本来就要滚动、会被裁切、点
外面就关掉，放在主区域反而更顺手。

两个坑与最终做法都写进了 `webui/Main.py` 对应位置的注释，测试在
`test/services/test_task_panel_widget_cost.py`。

## 已实现：工具台（Tools Bench）✅

落地页就是工具台。左侧导航最上面一组「工作台 / Tools」，一屏九张卡，每张卡写清
"它做什么"以及**此刻能不能用**。

状态只有三个，且都来自真实判定，不另设一份清单：

| 状态 | 判定来源 | CTA |
|---|---|---|
| `ready` 就绪 | 凭据已配 / 能力纯本地 | 「开始使用」→ 对应那一屏 |
| `needs_setup` 待配置 | 缺免费额度密钥 | 「去配置」→ 设置页 |
| `waiting` 等待中 | 缺前置产物（缩略图要先有完成的任务） | 仍给入口，但同时说清还差什么 |

未就绪的卡**不**跳到那个用不了的控件前——跳过去只会让人对着空控件发呆，而缺的是
密钥，那里根本没有填密钥的地方。

连带修掉的真问题：就绪度原先只读单数键 `pexels_api_key`（设置页写的是复数
`pexels_api_keys`），并且从 `config.app` 里取 Azure 凭据（实际存在 `[azure]` 段的
`speech_key`）。于是**配好了密钥的用户永远被告知"未就绪"**——一个专门用来回答
"到底能不能用"的指示器，在最需要它的时候说谎。

刻意不照抄参考设计的三处（理由都写在 `webui/styles.css` 注释里）：卡片顶部不放
16:9 图（没有定制素材，一个只放字母的空盒子看起来就像图片加载失败）、CTA 一律用
次级按钮（九个实心主按钮会把整屏变成一片红）、正文不用 9px（那是把内容压进
768px 网格的代价，桌面上是负担而不是质感）。

工具台**绝不**自己提交生成或发布任务：提交前有约 280 行校验（素材源有效性、
各源密钥、本地素材条数），任何第二条提交路径都会跳过它们，于是任务只在服务端
失败，而用户看到的是一次成功的点击。
